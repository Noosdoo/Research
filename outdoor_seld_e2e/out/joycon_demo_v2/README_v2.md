## 3. 操作

| キー | 動作 |
| --- | --- |
| ←/→ | クリップ切替 |
| Space | 再生/停止 |
| S | 左右入替 |
| **M** | **束ねモード ON/OFF**（既定ON）: 同じ手・同じ段の再トリガが1秒以内なら振動を延長するだけ。画面に「通知N回 / 束ねた再トリガN回」 |
| **G** | **連続モード ON/OFF**（既定OFF）: 車・キック・バイクは緊急度（予測最接近・到達時間から 0..1）で振動の強さが連続に変わる。安全→注意→至近で徐々に強くなる。警告音の単発はそのまま |
| **D** | 検出層の出力（暗い円盤）の表示 ON/OFF |
| **V** | 街の飾り（交差点・信号・建物・街路樹）の表示 ON/OFF。見た目だけ |
| **B** | Joy-con が4本のとき、前ペア/後ペアの入れ替え |
| **R** | **Joy-con の役割割当**（4本のとき）: 押すと割当モード。画面の指示どおり「前左」で持っている本のボタン（ZL/ZR/SL/SR/十字/スティック押込）→「前右」→「後左」→「後右」の順に押す。押した本が 0.3 秒震えて確認。接続順（HID の列挙順）は持ち方と一致しないので、**4本つないだら最初に R で割り当てる** |
| **T** | 役割の順（前左→前右→後左→後右）に 1 本ずつ 0.5 秒震わせる。どれがどれか手で確かめる |
| **J** | **系列切替の合図 ON/OFF**（既定ON・連続モード時）: 緊急度が続いているのに方位が0.3秒以内に60°以上跳んだ＝追跡が別の車に乗り移ったとみなし、新しい側で短い2連の合図を出してから連続振動を弱いところから立ち上げ直す。「同じ車を追えていない」ことを逆に「別の車が来た」の合図に変える案 |
| **P** | **パンニング ON/OFF**（既定ON・連続モード時のみ）: 方位に応じて左右の振幅を按分（正面=両手半分、真横=片手だけ）。方向も段階的に伝わる。⚠️ Joy-con 2本では前後を区別できない（首元4〜6方向デバイスなら隣の振動子への按分にする） |

## 3.5 画面（俯瞰ビュー v2）

- **歩行の場面は街が後ろへ流れる**（2026-09-03）: 歩行者（白いカプセル）は画面中央に固定し、車線・飾り・地図を歩く速さで後ろへ動かす。配置図は「5 秒時点の歩行者」基準なので、5 秒でちょうど原点に来る

- 画面の文字は左上（操作）・右上（凡例）・下（判定）の半透明パネル。行ごとに高さを計算して折り返す

- 道路の配置: 車線（横位置・進行方向の矢印）・歩道（足元の帯）・踏切（線路・遮断機・X標識）・**横切る道路／線路／高架（v3 の xlane 行）** を `_layout.csv` から描く。
  本物の横切る道路がある場面では飾りの交差点はその位置に合わせる。⚠️ 歩行の場面では道路の位置は 5 秒時点の歩行者基準（画面上は歩行者が原点固定）

## 5. 「振動は徐々に強くなるか」への答え

- **今の設計（G=OFF）は2段の離散**: 「中（2発・弱）」→「強（4発・強）」で、中の後に強へ昇格したときに強のパターンが出る。
  安全（抑制）は無振動。徐々にはならない
- **G=ON は連続案の試作**: 予測最接近が 1.6m→1.3m、到達時間が 4s→2.5s に近づくほど振幅と周波数が上がる（0.25→1.0）。
  規則の発火判定（4フレーム確認）は使わず、毎フレームの判定材料をそのまま振動にしている＝**早いが揺れる**
  （予測の揺れがそのまま手に来る）。離散と連続のどちらが分かりやすいかは体感で決める

## 5.3 検出層はデモに入っているか

**⚠️ 場面 01〜28（フォルダ 1〜5, 7）は検出層を通していない「オラクル」です。** 正解の位置（GT）に通知規則 v4.3 を当てただけで、
モデルは使っていません（cues.csv の末尾にも明記）。**本物のモデルを通しているのはフォルダ 6（A〜D）だけ**。
2026-09-03 本人指摘を受け、28 場面を本物の検出層（因果推論 ft2 e099）に通した版を **作成済み（フォルダ 8）**。手順:
`_make_custom_demo_scenario_v3.py --save-foa` で 4ch 音とラベルを `model_infer/` に保存 → サーバで `server_sde/custom_infer.sbatch`
→ 予測から通知を作り直す。できたら「8_自作場面_本物のモデル出力」として並べ、オラクルと見比べる。

**「振動が遅い・間に合っていない」（フォルダ 6 で本人が体感）**: それが本物のモデルの限界です。因果推論（過去の音だけ）＋規則の
4 フレーム確認＋hold の分だけ遅れ、開発用 val では**強の先行時間の中央値 1.0〜1.2 秒、2.5 秒以上先行できるのは 2 割**（④の表）。
車が真横に来てから震えることがあるのはこの数字どおり。オラクル（1〜5, 7）は規則の遅れだけなので、モデルの遅れが分かる比較になる。
Joy-con 側の遅れ（Bluetooth 0.05〜0.1 秒）は無視できる。

- **入っている**。通知（cues）は本物のモデル出力（因果推論の class/方位/距離）に v4.3 を掛けたもので、
  v2 からはその**検出層の生出力そのもの**を `_detect.csv` として画面に重ねる（暗い円盤・D で切替）。
  立体（GT）と円盤（検出）のズレ＝知覚層の誤差がそのまま見える。警告音クラスは方位だけなので半径15mのリング上に描く

## 5.4 前後の区別 — Joy-con 4本案

**2026-09-03 15:55 更新: 4本にすべてのモードが対応**。接続順で 左1本目=前左(+45°) 右1本目=前右(−45°) 左2本目=後左(+135°)
右2本目=後右(−135°)（B で前後ペアを入替、S で左右入替）。
- 離散通知（強=4連打・中=2発）・警告の単発・系列切替の合図: 通知の方位に**一番近い1本**が震える（2本のときは左右だけ）
- 連続モード（G）+ パン（P）: cos² の重みで4本に按分（方向が滑らかに移る）。パン OFF なら一番近い1本
- 束ね（M）は Joy-con ごと（前左で鳴った直後の再トリガは前左だけ延長）
- 画面の「最後の通知」に 前左/前右/後左/後右 と出る。JoyconLib は接続された Joy-con を全部列挙するので本数の上限はない

- できる（上記のとおり全モード対応）。接続順で 左1本目=前左(+45°) 右1本目=前右(−45°) 左2本目=後左(+135°) 右2本目=後右(−135°)。**もう1組（2本）が要る**（中古で5〜6千円）。
  首元デバイスの「4〜6方向」の先行知見（腰ベルト 8方向98%/首は鈍い）と同じ構図なので、4本で前後左右が
  分かるかは設計の直接の予備実験になる
- ⚠️ 手に持つ4本と首元4点では感じ方が違う（手の方が敏感）。「分かる/分からない」の下限を見る用途

## 5.5 「方向も段階的に伝えられるか」への答え

- できる（P=ON）。毎フレームの追跡系列の方位をそのまま左右の按分にしている。**同じ車が通り過ぎる間**は方位が
  滑らかに回るので、振動も左→正面→右のように移る
- ⚠️ 限界: 知覚層は同じクラスの車を**1本の系列**でしか追えない（同時検出62%）。同じ方向に車が続くと系列が
  別の車に乗り移り、方位が跳ぶことがある。跳んだときは「別の車が来た」と伝わる形になる（悪くはないが、
  同じ車を追い続けている保証はない）。これは通知規則の側では直せず、知覚層（多重車の分離）の課題

## 6. 記録してほしいこと（次の設計に使う）

1. A で M=ON にしたとき、束ねた後の「1回の長い振動」は自然か／短すぎ・長すぎか
2. B で G=ON の連続は「近づいてくる」感じがするか、それとも揺れてうるさいか
3. C は M=ON でも多いと感じるか（多いなら「流れモード」を長尺評価で作る根拠になる）
4. G+P で方向の移り変わりが分かるか／跳びが気になるか
