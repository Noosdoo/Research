## 1. 前提（Astraが知らない最小限）

- **研究**: 難聴者向けの屋外 SELD。1次アンビソニックス（FOA・4ch）で、8クラスの音の
  **種類・方向・距離**を同時推定し、危険度に応じて触覚（振動）で通知する
- **8クラス**: `siren` `horn` `backup_beep` `bike_bell` `car_drive` `crossing` `kick` `bike`
- **学習は合成データのみ**（SpatialScaper系の自作パイプラインで生成、確定評価セット1,800本）
- **実録210本は評価専用**（合成で学習したモデルの sim-to-real ギャップを測る）
- **機材**: Zoom H3-VR（4方向マイク）を**ヘルメットに載せて**装着。AmbiX 96kHz/24bit
- **通知層は現行 v4.3**。危険判定の窓は**最接近（CPA）の2.5〜1.5秒前**
- **絶対較正の規約**: フルスケール正弦波 ≡ 143 dB SPL。実録では騒音計の LAeq 読み値と
  録音内の暗騒音区間の**A特性レベル**を照合して全体ゲインを掛ける
  （`gain = 10**((laeq - measured)/20)`。`measured` は IEC 61672 の A特性で計算＝**A対A**で整合）
- **事前登録あり**。確定評価は1回だけと宣言済み。**12月末で全実験終了**
- 9/15のゼミで**機材購入を相談**する。それまでにプロトコルを固める必要がある

| # | 決定 | 変更前 | 理由として述べられていること |
| --- | --- | --- | --- |
| **D1** | 装着は**ヘルメット** | チェストハーネス | 体の上に出るので**体による遮蔽がほぼ無くなり**、学習データ（自由音場の合成）に近い。公道で三脚は立てられないが身に着けた機材なら許可不要 |
| **D2** | 方位校正は**初日に正面で手拍子1打**。推定方位角を度で読み、ズレが±10°超なら `--yaw` で補正 | 毎セッション、**ベルを前後左右4方位から3mで1打ずつ** | マイクの正面＝自分の正面であることさえ確かめればよく、4方位ぶんの情報は使っていなかった。協力者も不要になる |
| **D3** | 記録は**録音とストップウォッチを同時開始→最接近でラップ→その場でスマホに手打ち** | 手拍子で時刻同期＋**声のスレート**＋**スマホ動画**（±0.2秒級） | 公道で声を出さずに済む。他人の車・顔・ナンバーを撮らずに済む。ラップの役割は「波形のどの山がどのイベントか」の特定だけで、t_cpa 自体は波形から読めるので1〜2秒のズレは害にならない |
| **D4** | **象限＝マイク基準・最接近の2.5〜1.5秒前**の向き | 「体から見た前後左右」（時点の定義なし） | 通知層の判定窓と一致させる。体の向きは記録しない（ヘルメットなのでマイク＝体の正面） |
| **D5** | **走行音が少しでも重なれば1行にまとめて `n_car` を増やす。秒数の閾値は設けない** | 規定なし | 採点は「そのイベントで通知が出たか」なので、重なった2台を分けてもどちらへの通知か区別できない |
| **D6** | **実録は学習に使わない**（評価専用） | （本人は学習に使うつもりでいた） | 学習には0.1秒ごとの方位・距離の正解が要るが、実録では取れない。実録で学習すると「合成だけで学習したモデルが実環境で通用するか」という問い自体が壊れる。量も足りない（合成7,200 vs 実録210） |
| **D7** | 騒音計は **LAeq（積分）表示が必須**。学内借用が本命、次にレンタル、購入は仕様書に「Leq／等価騒音レベル」があるものだけ | 「1万円程度で買う」想定 | LAeq は60秒ぜんぶを1つにしたエネルギー平均で、瞬時値だけの機種では作れない。廉価品（例: サンワサプライ CHE-SD1）は MAX/MIN と Fast/Slow のみで Leq が無い。Leq 付きは 2〜4万円が下限、確実なもの（リオン NL-42 等）は10万円級 |
| **D8** | **風防は必須。ZOOM 公式が WSU-1 を別売として掲載しているため「別途購入」に訂正**（初稿の「同梱」は誤り） | 「同梱なので不要」 | 風の音は音場ではなく**風が振動板を直接叩く近接雑音**。4chそれぞれ叩かれ方が違うので**4chのバランスが崩れて方向推定が壊れる**。学習データに風雑音は無い |

## 3. こちらが自分で見つけて直した欠陥（1件・参考）

**F1（重要度: 高）— 正面校正の合格判定が粗すぎた。**
初稿では「手拍子1打を録って**推定が『前』と出れば合格**」としていた。
だが象限は90°刻みなので、**ヨーが30°ずれていても「前」と出て合格してしまう**。
校正の意味がない。

→ **推定方位角を度で読み、そのズレ角を記録する**方式に変更。±10°超は
step19 の `--yaw` に渡して補正する。CSVの列も `正面校正OK`(y/n) →
`正面ズレ_deg`(数値) に変えた。

**この種の欠陥が他にもある前提で見てほしい。**

## 4. こちらが疑っている弱点（先出し・ここ以外を優先してほしい）

| | 疑い |
| --- | --- |
| **W1** | **D3の副作用**: 動画をやめたので、車種（EV/HV/ガソリン）が**目視のみ**になった。EVは「静かなので層別で見る」と位置づけている主役なのに、走行中の車をヘルメット装着で目視して EV と HV を確実に区別できるのか |
| **W2** | **D3の前提**「t_cpa は波形から読める（真横で音量最大）」が、**EV・徐行**では崩れないか。ピークが不明瞭ならラップ1点だけでは足りない |
| **W3** | **D5の採点帰属が未決**。`n_car=2` の1行に対して「どちらの車への通知でも到達」と数えるなら**甘くなる**。第11回監査でも「採点の帰属方式」は要決定として残っている |
| **W4** | **D8と研究の趣旨の緊張**: 風防で風を消すのは測定を綺麗にするためだが、**実用では風は吹く**。sim-to-real を測るのに現実の一部を排除していないか |
| **W5** | **D6を「物理的に無理」と断言した点**。フレーム単位の正解が要るのは教師あり学習の話で、**ドメイン適応（特徴統計の整合など）なら粗いラベルでも可能**では。「使えない」は言い過ぎではないか |
| **W6** | **D2・D3は事前登録の「縮小」**（観測項目の追加ではない）。手順書に「事前登録の更新対象」とは書いたが、**正式な変更記録はまだ作っていない** |
| **W7** | **210本（うち象限が付くのは一部）で、4分類の正解率にどれだけの検出力があるか**。信頼区間を出したら何も言えない幅にならないか |
| **W8** | **D10**: サイレンは統制できないので、**遭遇待ち8本が揃わないリスク**。揃わなかったときの扱いが決まっていない |

1. **内的整合性**: D1〜D12 の間で矛盾していないか（例: D4の「マイク基準」とD1の装着方式、D5とD12）

## 6. 出してほしい形式

```
判定: 合格 / 条件付き合格 / 不合格
指摘リスト:
  [高] 指摘の要旨 — 根拠 — 影響 — 提案
  [中] …
  [低] …
残条件（条件付き合格の場合）: 何を満たせば合格か
```

**自己申告は証跡にしない**という運用にしている。この文書の記述が根拠として弱いと
判断したら、**「根拠不足」として指摘に含めてよい**。
