## 指摘リスト

### R01［高・新規／実装確認］60秒の校正値を、別の20〜30秒テイクに渡す手順がつながっていない

**根拠**：[当日手順](../design/実録_当日の手順書_車の収録_2026-09-05.md) L76–89はセッション冒頭の60秒校正、L108以降は別々に開始・停止する20〜30秒の本番録音。[CSV README](../design/実録_記入用CSV_2026-09-05/README.md) L142–146は、その本番 `raw/take01.wav` に `--laeq-window 10-70` を渡す例になっている。

しかし [step19](../../scripts/step19_realsmoke_convert.py) L57–74、77–96は、**指定された入力ファイル自身の区間**からゲインを計算する。25秒の4ch・96kHz WAVで再現すると、通常変換も `--gain-only` も `laeq-windowが録音長を超えています` で停止した。

**影響**：窓を本番音の長さへ縮めて回避すると、別時刻の車音にセッション冒頭のLAeqを対応させる誤校正になる。また当日手順L200は音割れ時にゲインを下げる指示があるが、再校正・校正ID更新の指示がない。同じ補正量を継承すれば、変更したゲイン差がそのまま音量誤差になる。

**提案**：校正録音を独立したファイルとして識別し、そこから補正量を一度計算する。全テイクに `calibration_id`、録音機のゲイン設定、補正量、原本ファイル名を紐付ける。既存の `step19 --gain-only` → `step19b --gain-db` の経路を本番にも使える。ゲイン・設定変更時は校正を更新する。地点移動だけなら、同一の測定系・ゲインを保っている限り「毎回その地点の暗騒音に正規化する」必要はない。

### R02［高・新規／実装確認］実録採点器が v4.3 を使っておらず、前方除外も実装されていない

**根拠**：依頼書L30は現行通知をv4.3とする。一方、[ハンドブック](../design/実録ハンドブック_2026-08-13.md) L212–215が指定する [step20 v2](../../scripts/step20_realsmoke_score_v2.py) は、L7–16、59–65にある**旧v3.4の距離閾値・連続フレーム規則**で通知を作り直す。[v4.3本体](../../scripts/step12_notify_v43.py) のCPA・方位変化率の処理を呼び出していない。

加えて、ハンドブックL157–161とCSV README L130は `F` を既定で除外・別集計すると説明するが、step20 L305–308、464–479は `F` も同じ分母に入れる。再現入力の `quadrant=F` は採点対象に残った。

**影響**：「現行システムの実環境成績」「視野外イベントの通知到達率」と説明しても、その数値を算出していない。実録だけ旧規則で評価すれば、合成との差に通知規則の違いが混ざる。

**提案**：採点対象のモデル・通知規則・設定ファイルを明示して固定し、実録採点をその正規実装に接続する。旧規則を比較対象として残す場合は別名で報告する。前方を除外する仕様を採用するなら、件数・分母・別集計を実際の出力で確認する。

### R03［高・新規／実装確認］「CPAの2.5〜1.5秒前」は通知採点窓ではない。現在の象限比較は時点がずれる

**根拠**：依頼書L30、D4、CSV README L49–58は、この1秒を通知の判定窓として象限を記録させる。しかし [Q2型別表](../../scripts/_notify_v42_q2_table.py) L54–69では、これは**GT方位変化率から対向型／すり抜け型を分類する窓**。同ファイルの通知結果の窓は `[イベント開始−1秒, CPA＋1秒]` である。[v4.3帰属評価](../../scripts/_notify_v43_attrib.py) L6–9も、型分類と通知の帰属を分けている。

実録step20 L335–368は広いイベント窓内の発火を選び、**発火した時刻の方位**を1つの `quadrant` と比較する。再現例ではCPA=8秒に対する8.4秒の発火も成功となり、リードは−0.4秒だった。これは「実装が依頼書の1秒窓を使っていない」証拠であり、既存の広い窓そのものをバグと断定するものではない。

**影響**：CPAの2秒前には後方、発火時には右側にいる車で、双方の時点の方向が正しくても象限不一致になりうる。さらにL470、493の象限一致率は**通知できた例だけを分母にする条件付き指標**で、未検出は分母に入らない。「全イベントの方向正解率」と呼ぶと過大に解釈される。

**提案**：①接近の型を決める時点、②通知を成功とする時間窓、③方向の正誤を比較する時点を別々に定義する。方向は同時刻のGTと比較するか、独立に定義した固定窓内の推定とGTを比較する。窓内で象限をまたぐ場合の扱いも決める。通知率と「通知成立例に限る方向一致率」は分母を併記する。**採点窓を単に1秒へ狭める修正は、別の評価変更なので自動採用しない。**

### R04［高・新規／実装確認］現場CSVを結合するだけでは解析入力にならず、必要な変換規則が欠ける

**根拠**：CSV README L3–5はBASE_COLSへそのまま転記できると説明し、当日手順L213–219は「変換→切り出し→表の結合」の順。[step19b](../../scripts/step19b_realsmoke_cut.py) L319、336は**切り出し前に原注釈CSVとCPA時刻が必要**で、波形からCPAを自動推定する処理はない。

配布例の `session.csv` と `例_記入済み.csv` を単純結合して [step19c](../../scripts/step19c_ann_validate.py) に渡すと、`clip_id, trial, quadrant, t_start, t_cpa` の5列不足で停止する。列名の変換で済むものと、新たな観測・注釈が必要なものが混在している。`scripts` / `src` の検索では `ラップ秒`・`正面ズレ_deg` の取込処理は見つからなかった。

`take_id` は現場では1、2、3…の例だが、step19c L204–220はセッションをキーに含めず全体で一意として扱う。別セッションの同じ `take_id=1` をまとめると原録音不一致で失敗する。原本名との対応や、校正録音を本数から除く規則も現場CSVにない。

**影響**：手作業を補えば進められるが、記載どおりの一連の処理は実行できない。原本・時刻・校正の対応を収録時に失うと後で正しく補完できない。

**提案**：`session_id×take_id` を一意キーにして原本名を保存する。`象限→quadrant`、`歩行対比→歩行` 等の対応、`trial`、イベント開始 `t_start`、CPAの注釈方法、負例の担当区間を明文化する。原注釈を作ってから切り出す順序に直し、2セッション・校正・正例・負例・複数イベントを含む模擬データを一度最後まで通す。

### R05［高・W2を具体化／測定根拠不足］音量最大の時刻を、幾何学的な最接近の正解にできない

**根拠**：当日手順L128–130、ハンドブックL176–180は「真横で音量最大」「ラップ1〜2秒のずれは害にならない」とする。これはEVだけの問題ではない。単純化して受音振幅を `A(t)/r(t)` と置いても、音源の出力 `A(t)` が変動すれば、その最大時刻は距離 `r(t)` の最小時刻とは一致しない。加速、警告音の発音時刻、反射、別の車の音を、この手順は独立に区別できない。

また「同時にボタンを押す」という操作だけでは、録音開始遅延と操作遅延を測ったことにならない。現在のラップは録音時刻に共通の同期証拠を残さない。

**影響**：CPA・リード時間・固定時刻の方向GTが同時にずれる。モデルも利用する音量情報からCPAの正解を決めるため、音響的に見つけやすいピークへ正解が引き寄せられる危険がある。誤差の実測値はまだなく、現時点で何秒ずれるかは断定できない。

**提案**：CPAはあらかじめ定めた通過位置の独立な観測から取る。動画に限定せず、録音と同期した観測時刻の記録などでよいが、採用方式の誤差を予備試験で測る。正解時刻の不確かさを保存し、許容幅・境界例の扱いを事前に固定する。音量ピークは補助情報とし、CPAへ無条件に置換しない。独立時刻を取らないなら、精密なリード・固定窓方向評価の主張を縮小する。

### R06［高・W3を具体化／実装確認］複数車を1行にすると、採点以前に正解の意味が決まらない

**根拠**：D5、CSV README L67–78は少しでも音が重なれば1行にする。一方、[events.csv](../design/実録_記入用CSV_2026-09-05/events.csv) が持つCPA・象限・車種・横距離は各1値だけ。例えば右2mの車と左5mの車が重なると、どちらの距離と象限を記すか決まらない。

step20は `n_car` を採点に使わない。再現例では1から2へ変更しても結果は完全に同じだった。また同時刻の左右の車に対する車両別の正しい通知を、単一の象限ラベルでは採点できない。合成側の方位帰属評価は時刻ごとのGTを使うため、そのまま実録へ移植することもできない。

**影響**：車両ごとの到達率・多重車層の性能と、「何か1回通知された割合」が混ざる。観測時に個体情報を捨てると、後から帰属方式を決めても復元できない。

**提案**：原記録は可能な限り1車両1行を保ち、重なりは `overlap_group_id` 等で表す。どの車への通知か確定できない例はその旨を記録する。車両単位の主要評価から外す場合も事前規則と除外件数を残す。1行を保つなら「群内のいずれかへの通知」という別の指標として定義し、単車の到達率や車両別の合成成績と同一視しない。

### R07［高・W6を拡張／文書間の不整合］現行の事前登録と評価データの用途が一意に決まっていない

**根拠**：[スモーク計画書](../design/実録スモーク計画書_2026-07.md) の「現行の事前登録」R4（L220–229）は胸部装着とその条件下の主張を定めるが、新手順は全ヘルメット。R7 L269–270は歩行対比を同一セッション・同一車両・同一運転者とし、テイクごとのLAeqも記録するが、新CSVはLAeqと区分をセッション側に1値だけ持つ。単なる表記変更ではない。

さらに依頼書L28と新CSV README L153–154は実録210本を評価専用とする一方、[調整用と最終評価用の分離案](../design/実録_調整用と最終評価用の分離_2026-09-05.md) L18、22は210本の1/3を調整に使う案。**後者が案であることは明記されているため、実際にデータ漏洩したという指摘ではない。** どちらを採用するかが未確定で、現場CSVに用途列もないという指摘である。

**影響**：実録を見て音色・生成条件・閾値を調整したモデルを、その実録で外部検証すれば、勾配更新に使っていなくても独立な最終評価とはいえない。装着・観測精度・分母の変更後に旧事前登録のままと扱うこともできない。

**提案**：収録前に変更票を1つ作り、置換する節、採用理由、主要評価・対象条件・採点器の版・実録の用途を固定する。調整用を設けるならセッション単位等で事前分離し、最終評価の封印と例外的な品質点検の担当・範囲を定める。全210本を評価専用にするなら、その録音を用いたモデル・通知規則・合成条件の調整を行わない規則に統一する。

### R08［高・新規、超音波評価に限定／論理的不成立］受信できる可能性は、統制発信器が不要な理由にならない

**根拠**：D9と機材リストL209は「96kHz収録で拾えるのでHC-SR04を削除」とする。しかし [収録計画v2追補](../design/実録収録計画v2追補_2026-07-28.md) L56–68は、既知の40kHz発信と事前試験でH3-VRの実効的な受信能力を確認する設計。[ハンドブック](../design/実録ハンドブック_2026-08-13.md) L32、42–43にも発信仕様・SNR基準の事前登録が残る。

96kHzの標本化は40kHzをデジタル的に扱える条件の一つだが、マイク・アナログ経路を通った信号の検出能力を保証しない。読んだ[メーカー取扱説明書](https://zoomcorp.com/media/documents/E_H3-VR_2.pdf)の仕様欄には96kHz録音はあるが、40kHzの感度保証は確認できない。

**影響**：自然環境で40kHz成分が見えなかったとき、発信源がいないのか、受信できないのか分離できない。統制された検出率や不成立判定を出せない。

**提案**：既知発信源と事前試験を残すか、統制超音波評価を正式に範囲から外す。自然録音だけなら探索的な観測と明記する。原本96kHzを別途保持する実装は既にある（step19 L4–6）。24kHzへ変換してしまう欠陥がある、という指摘ではない。超音波評価を外せば、この項目は8クラスの可聴音評価の開始条件から外せる。

### R09［中・F1の残り／識別性の反例］度で読む修正は正しいが、正面1打だけで座標系全体の校正は終わらない

**根拠**：D2、当日手順L93–104には角度を推定する手段・信頼性・再測定基準がなく、初日の1打だけで以後の整合を保証する。数学的に `Y→−Y` の左右反転があっても、正面ベクトル `(1,0,0)` は変わらない。正面の推定値が0°でも左右反転は見逃す。これは**実際のH3-VR録音に左右反転があるという報告ではない**。

正面1方向は任意の3軸回転を決める十分な観測でもない。水平器の使用は補助になるが、頭にかぶり直したときの位置や傾きまで、アダプターのねじ締めだけで固定されるわけではない。

**影響**：符号・チャンネル・装着方向を確認したという主張が実際の検査範囲を超える。8クラスに含まれない手拍子を、クラス検出に依存するモデルからどう読めるかも未定義。

**提案**：導入時は既知の複数方位で軸・符号・順序を検証する。毎回同じ4方位を録る必要性とは分けて、再装着・設定変更後の短い点検を定める。手拍子を使うならクラス検出と独立した方位算出方法、信頼度、補正後の確認を示す。なお「右が＋」の記録値+30°を `--yaw +30` へ渡す符号は、現実装のベクトル回転では正しく0°へ戻った。符号逆転を欠陥とはしない。

### R10［中・新規／実装確認］録音開始と例示された時刻では、CPA前8秒を確保できない

**根拠**：当日手順L112は車の来る気配がしてから録音する。配布例にはラップ5.2、6.1、7.5、7.8秒がある。CPAをこれらの値と仮定して `plan_event_cut()` に渡すと、先頭0秒へクランプされ、CPAはクリップ内8秒にはならない。後ろを長く録っても、失った前方の時間は戻らない。

**影響**：前8秒という既存の条件が保証されず、追跡や時系列特徴の立ち上がり条件が変わる。さらに気づいた通過だけを録る場合、気づきにくい車をどれだけ逃したか測れない。ここで「気配」を必ず音による検出と決めつけることはしないが、抽出基準の未定義は残る。

**提案**：固定した時間帯の連続収録や十分早い開始で必要な履歴を確保し、対象通過の数え方を先に決める。履歴不足のテイクはフラグを付け、主要評価への採否を固定する。選択された場面のスモーク試験に限定するなら、一般の通過車全体の性能とは区別する。

### R11［中・新規／未検証の仮定］ヘルメット装着を「ほぼ自由音場」と扱う根拠がなく、横距離の基準も曖昧

**根拠**：D1、機材リストL68–71は体遮蔽がほぼ消えるとするが、頭・ヘルメット・マウント・風防を含む構成の方位別測定は提示されていない。装着高さの変更も音源との幾何・地面反射条件を変える。

また当日手順L62は「車道から横2.0〜3.2m」を鳴るべき車の帯とするが、採点器が必要なのは**対象車の通過経路に対する横距離**である。縁石から2mと、車の経路から2mは同じではない。3.2m付近を目測だけで合否に分ける際の不確かさの扱いもない。

**影響**：ヘルメット条件で得た成績を胸部装着や自由音場へ一般化できない。距離の基準を取り違えると、caution/safeの正解区分そのものが変わる。現時点で何dB・何度悪化するかは未測定。

**提案**：まず主張を実際のヘルメット構成下の結果に限定し、装着高・向き・風防・固定方法を記録する。自由音場へ近づいたと主張する場合だけ、比較測定を追加する。横距離の基準点を図示し、公道で不確かな境界例は範囲を保存して別扱いにする。静止A試行の「頭を動かさない」指示は既にあるため、その指示自体が無いという批判はしない。

### R12［中・W1／正解の品質管理不足］EV/HVの層別は、車種の確認方法と確度を分ける必要がある

**根拠**：CSVは `EV/HV/ガソリン/大型/不明` の1列だけ。既に「不明」がある点はよいが、目視による推測と所有者等に確認した情報を区別できず、`大型` は動力方式と別の分類軸である。

**影響**：静かな車を音でEVと判断すると、音の静かさで選んだ群をEVの性能として評価する循環が生じる。HVであることだけでは、その通過時のエンジン稼働状態も確定しない。動画があれば必ず解決するという問題でもない。

**提案**：動力方式、車両区分、確認方法・確度を分ける。主要なEV比較は確認済みの統制車両等を中心にし、自然観測の未確認例は不明群として件数を出す。走行音だけでEV/HVを確定しない。

### R13［中・W5／理由の誤り］評価専用という選択は成立するが、「実録は学習に使えない」は言い過ぎ

**根拠**：ハンドブックL185–186の断言は、位置正解を使う教師ありSELD学習と、それ以外の学習方法を混同する。[DCASE 2024 Task 4の公式説明](https://dcase.community/challenge2024/task-sound-event-detection-with-heterogeneous-training-dataset-and-potentially-missing-labels)は、弱ラベル・未ラベルの実音と合成の強ラベル音を学習に使う構成を示す。これはこの研究の8クラスSELDで直ちに有効という保証ではないが、「密な位置ラベルがなければ一切学習に使えない」という一般論への反例にはなる。

**影響**：研究設計上の選択が物理的制約として説明され、将来の適応実験やデータ保存の価値を誤って狭める。

**提案**：「今回は合成のみで学習したモデルの評価を主目的とし、実録をモデル・規則の調整に使わない」に改める。適応研究は、独立した最終評価を別に確保した別実験として扱う。今回の監査を理由に実録学習を追加する必要はない。

### R14［中・新規／根拠不足］「身に着けた機材なら道路使用の確認は不要」と一律には言えない

**根拠**：当日手順L65、機材リストL71は装着方式だけで不要と断言する。しかし[警察庁の説明](https://www.npa.go.jp/bureau/traffic/seibi2/shinsei-todokede/dourosiyoukyoka/permission.html)は、道路の使用行為や交通への影響で整理している。また[千葉県警が掲載する規則第11条](https://www.police.pref.chiba.jp/content/common/000065173.pdf)は、対象行為にロケーション・撮影会・街頭録音会を挙げる。

**影響**：装着方式だけを根拠に、場所・人数・反復走行等を含む実施形態の検討を省いてしまう。**今回の単独・受動的な録音がこれらに該当する、または違法だとは本監査では判断していない。**

**提案**：装着＝一律不要、三脚＝一律不可という断言を外す。既存ハンドブックL67のように、受動観測と設置・反復走行等を分け、対象地の具体的な実施形態について判断した根拠を残す。[個別の問い合わせ先は管轄警察署交通課](https://www.police.pref.chiba.jp/faq/permit.html)。

### R15［低・新規／説明の精度］風防の同梱・別売は、フォームとファーを区別する

**根拠**：[ZOOM公式の米国向け同梱一覧](https://zoomcorp.com/en/us/handheld-recorders/handheld-recorders/h3-vr-360-audio-recorder/)にはフォーム風防が含まれ、WSU-1のファー風防は別売。[日本向け製品ページ](https://zoomcorp.com/ja/jp/handheld-recorders/handheld-recorders/h3-vr-360-audio-recorder/)にもWSU-1は別売アクセサリーとして掲載されている。

**影響・提案**：D8の「WSU-1が別売なので風防は同梱でない」という一般化は正確でない。ただし機材リスト§④は明確に「もふもふタイプ」を指定しており、**ファー風防を別途予算に入れる判断自体は否定しない**。フォーム付属と屋外用ファー追加を分け、実際の購入・レンタル品の付属内容を確認する。

## 合格へ進むための残条件

1. **正規の評価を固定する**：採点器・通知設定・対象方向・時間窓・GTと比較する時点・分母を一意にする。v4.3を評価するならその発火との一致を確認する。
2. **現場記録から採点までを一度通す**：校正ファイルから補正量を継承し、原本と一意IDを照合する。短い本番、負例、複数イベント、複数セッション、ゲイン変更を含む模擬例で、CSV変換・切り出し・検査・採点を完走する。
3. **後から取り返せないGTを先に守る**：独立なCPA時刻、方向を決める観測、複数車の正解単位、必要な録音履歴について方式を確定し、予備試験で誤差と失敗条件を確認する。測らない項目は評価の主張から外す。
4. **校正点検と装着条件を明文化する**：導入時の軸・符号確認、再装着時の点検、校正更新条件、装着高、横距離の基準点を残す。
5. **事前登録を更新する**：ヘルメットへの変更、収録方式、実録の用途、除外・不足規則を統合する。調整用を設ける場合は最終評価を事前分離する。
6. **超音波の範囲を決める**：統制発信による事前試験を維持するか、統制超音波評価を撤回して探索扱いにする。

上のソフトウェア再現例は監査時点の不整合を示したもので、修正後の合格試験ではない。修正後は「エラーが消えた」だけでなく、期待する発火・分母・時刻・校正量になった結果を証跡にする。

## 9/15の相談に持ち込む内容

借用優先は購入相談と矛盾しない。必要な機能、貸出日程、校正状態、付属品、借りられない場合の実際の見積を順番に確認する資料にすればよい。H3-VR・装着部材・風防に加え、**校正と時刻・方向GTの予備試験を実施できる日程と協力体制**を相談項目に入れる。

「監査合格済み」「このCSVだけで確定評価まで動く」「ヘルメットなら自由音場かつ確認不要」「96kHzだから超音波の事前試験不要」という説明では提出しない。修正予定・未検証事項を明示した相談資料として扱う。
