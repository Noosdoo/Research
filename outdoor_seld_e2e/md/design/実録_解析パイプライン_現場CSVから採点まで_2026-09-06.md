# 実録の解析パイプライン — 現場 CSV から採点まで（2026-09-06・監査 R01/R02/R03/R04/R10/W8 対応）

敵対的レビュー（Astra）で「記載どおりの一連の処理は実行できない」と指摘された経路を、**一本の規則**にした。
手順書・記入用 CSV の README（9/15 チャットが編集）は、この文書の規則に合わせる。

```
現場: session.csv（セッション 1 行）＋ events.csv（テイク×イベント 1 行）＋ 原本 wav（校正 60 s ＋ 本番 20〜30 s）
  │ step19d_field_csv_to_ann.py  … 現場 CSV → ann_orig.csv（一意キー session×take・列名の対応・t_start の規則・校正 id）
  │ step19_realsmoke_convert.py --calib <校正 wav> --laeq --gain-only  … 校正録音（全長）から補正量を 1 回だけ求める（calibration_<id>.json）。セッションごと
  │ step19b_realsmoke_cut.py --calib-dir <json の場所> --pitch/--roll/--yaw  … 原本から 10 s クリップを切り出し（原本ごとに自分の校正 id の補正量。未対応の原本・注釈があれば停止）
  │ step19c_ann_validate.py --ann ann_all.csv --cut --subplan "D:crossing=8,backup_beep=4,horn=4,siren<=4" [--strict]  … 検査（session×take の一意性・校正 id・D の内訳）
  │ 因果推論（_causal_infer_v17.py など・装着高さを入力）
  └ step20_realsmoke_score_v3.py --pred --ann  … v4.3＋hold で採点。方向は注釈窓の推定方位。前方/履歴不足/多重車は別集計
```

## 1. 現場 CSV の列（events.csv）と変換規則

| 現場の列 | 解析の列 | 規則 |
| --- | --- | --- |
| session_id, take_id | `take_id` = `<session>/<take>`、`clip_id` = 原本の stem（`原本` 列があれば。無ければ `<session>_take<NN>`） | 別セッションの take 1 が衝突しない |
| 原本 | `orig_file`（任意名可）。step19b は `orig_file` で音声と照合し、未対応があれば停止 | 録音機のファイル名をそのまま使える（N01） |
| session.csv の 用途 | `用途`（最終評価／調整用）。調整用の行は `ann_orig_tuning.csv` に分離 | A′・N06 |
| class | `class` | 8 クラス＋none |
| 象限 | `quadrant` | F/B/L/R。**最接近の 2.5〜1.5 秒前**の向き（step20 v3 はこの窓の推定方位と比べる） |
| ラップ秒（距離クラス） | `t_cpa` = ラップ秒（前端が肩の線を通った瞬間・補正なし） | `t_start` = t_cpa − 6 s（`--pre`）、負なら 0。始まりは注釈しない（`t_start_rule` 列に記録） |
| ラップ秒（警告音クラス） | `t_start` = ラップ秒（音の始まり）、`t_cpa` = ラップ ＋ 3 s（`--warn-span`） | 成功窓 [ラップ−1, ラップ＋4]、方向はこの区間の推定方位 |
| n_car, 車種, 速度, 横距離m, 状態, pair_id, 特記 | そのまま | `pair_id` は `<session>/<pair>` |
| session.csv の 区分 | `区分`・`trial` | 歩行対比（pair_id あり）は 区分=歩行・trial=walk |
| session.csv の LAeq_dB・暗騒音区間_秒・校正原本 | `calibration_id` = 校正原本の stem（例 ZOOM0001）、`calib_file` | 補正量は step19 --calib が計算。切り出しは記録紙の区間と json の窓を照合 |

負例（class=none）: `t_start`=0、`t_cpa`=原本の長さ（`--audio-dir` から読む）。

## 2. 校正の引継ぎ（R01・N04）

- セッション冒頭の 60 秒校正を**別ファイル**にする（記録紙の `校正原本`・例 `ZOOM0001.wav`。校正 id はその stem）。`step19 --calib` は**ファイル全長**（`--laeq-window` 省略時）から補正量を 1 回だけ求め、
  `calibration_<id>.json` に残す。騒音計で測った区間と音声の区間を同じにする（60 秒測ったら 60 秒）。本番テイクからは LAeq を測らない
- 録音機のゲインを変えたら校正を取り直し、`calibration_id` を変える（同じ id のまま補正量を使い回さない）
- `step19b --calib-dir <json の場所>` で、各原本の注釈の `calibration_id` から補正量を引く（2 セッションを同じフォルダで処理しても取り違えない。CLI の id と注釈の id が違えば停止）。
  全行に `calibration_id`・`gain_db` が付き、`step19c --cut` は空の行を警告する

## 3. 採点（R02/R03）

- `step20_realsmoke_score_v3.py`: 通知規則は **v4.3（winner.json）＋警告音 hold** の正規実装。成功の窓 = [t_start − 1 s, t_cpa ＋ 1 s]
- 時間指標: 距離クラスは **リード = 最接近（ラップ）− 発火**、警告音は **遅れ = 発火 − 鳴り始め（ラップ）**。別々に集計（N02）。方向は距離クラス＝注釈窓、警告音＝鳴り始めから 1 s
- 歩行対比（pair_id あり）は ablation の主要評価に入れない（静止側も）。別集計で**検出フレーム率**（主指標）と到達、pair ごとの静止−歩行の差を出す（N05）
- 方向 = 注釈の窓（CPA の 2.5〜1.5 秒前）の**推定方位の中央**を 4 象限に丸めて注釈と比較（発火時刻の方位ではない）。
  分母は「全イベント（未検出は不一致）」と「推定があった例」の両方
- 前方 F は主要評価から除外して別集計（`--include-front` で含める）。履歴不足（クリップ内 CPA < 7.5 s）と多重車（n_car ≥ 2）も別集計
- 旧 `step20_realsmoke_score_v2.py`（v3.4 規則）は比較用に残す。報告では「v3.4（旧）」と明記

## 4. 区分 D の内訳と機会枠（W8・N03）

- `step19c --subplan "D:crossing=8,backup_beep=4,horn=4,siren<=4"`: 踏切 8・バック音 4・クラクション 4 は必須（ちょうど）、サイレンだけ 0〜4 の機会枠。
  D の総数は 16〜20 を許容。0 本や必須の欠落は警告（`--strict` で不合格）。`--opportunity D` のように区分全体を機会枠にしない

## 7. 校正の点検（R09・2026-09-06 15:50）

`scripts/step19e_check_azimuth.py --in raw/<点検原本>` が、指パッチン（手拍子）の衝撃音を時間順に拾い、FOA の強度から方位角（左が＋）を出す。
既定は 前・右・後・左 = 0/−90/180/+90 の並びを ±25° で判定し、左右反転・前後反転・XY 入れ替わり・90° 回転を言い当てる。
正面の値が `正面ズレ_deg`、10° を超えると `--yaw = −正面ズレ` を提示（step19 の rot_matrix と符号が一致することを T47c で確認）。2 日目以降は `--expect 前`。
