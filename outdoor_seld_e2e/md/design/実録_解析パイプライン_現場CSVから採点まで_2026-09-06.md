# 実録の解析パイプライン — 現場 CSV から採点まで（2026-09-06・監査 R01/R02/R03/R04/R10/W8 対応）

敵対的レビュー（Astra）で「記載どおりの一連の処理は実行できない」と指摘された経路を、**一本の規則**にした。
手順書・記入用 CSV の README（9/15 チャットが編集）は、この文書の規則に合わせる。

```
現場: session.csv（セッション 1 行）＋ events.csv（テイク×イベント 1 行）＋ 原本 wav（校正 60 s ＋ 本番 20〜30 s）
  │ step19d_field_csv_to_ann.py  … 現場 CSV → ann_orig.csv（一意キー session×take・列名の対応・t_start の規則・校正 id）
  │ step19_realsmoke_convert.py --calib <校正 wav> --laeq --laeq-window --gain-only  … 校正録音から補正量を 1 回だけ求める（calibration_<id>.json）
  │ step19b_realsmoke_cut.py --gain-db <補正量> --calibration-id <id> --pitch/--roll/--yaw  … 原本から 10 s クリップを切り出し（校正 id・履歴不足フラグを付与）
  │ step19c_ann_validate.py --ann ann_all.csv --cut [--opportunity D=8] [--strict]  … 検査（session×take の一意性・校正 id・機会枠）
  │ 因果推論（_causal_infer_v17.py など・装着高さを入力）
  └ step20_realsmoke_score_v3.py --pred --ann  … v4.3＋hold で採点。方向は注釈窓の推定方位。前方/履歴不足/多重車は別集計
```

## 1. 現場 CSV の列（events.csv）と変換規則

| 現場の列 | 解析の列 | 規則 |
| --- | --- | --- |
| session_id, take_id | `take_id` = `<session>/<take>`、`clip_id` = `<session>_take<NN>` | 別セッションの take 1 が衝突しない |
| （原本） | `orig_file` = `<session>_take<NN>.wav`（`原本` 列があれば優先） | 録音機のファイル名と対応表を残す |
| class | `class` | 8 クラス＋none |
| 象限 | `quadrant` | F/B/L/R。**最接近の 2.5〜1.5 秒前**の向き（step20 v3 はこの窓の推定方位と比べる） |
| ラップ秒 | `t_cpa` = ラップ秒 ＋ `--lap-offset` | 録音開始〜ラップの遅れは予備試験で測って `--lap-offset` に |
| — | `t_start` = t_cpa − 6 s（`--pre`）、負なら 0 | イベントの始まりは注釈しない。規則で決める（`t_start_rule` 列に記録） |
| n_car, 車種, 速度, 横距離m, 状態, pair_id, 特記 | そのまま | `pair_id` は `<session>/<pair>` |
| session.csv の 区分 | `区分`・`trial` | 歩行対比（pair_id あり）は 区分=歩行・trial=walk |
| session.csv の LAeq_dB・暗騒音区間_秒・校正原本 | `calibration_id` = `<session>_calib`、`calib_file` | 補正量は step19 --calib が計算 |

負例（class=none）: `t_start`=0、`t_cpa`=原本の長さ（`--audio-dir` から読む）。

## 2. 校正の引継ぎ（R01）

- セッション冒頭の 60 秒校正を**別ファイル**にする（`<session>_calib.wav`）。`step19 --calib` はそのファイルの `--laeq-window` から補正量を 1 回だけ求め、
  `calibration_<id>.json` に残す。本番テイクからは LAeq を測らない（短いテイクで窓が録音長を超える、という停止は起きない）
- 録音機のゲインを変えたら校正を取り直し、`calibration_id` を変える（同じ id のまま補正量を使い回さない）
- `step19b --gain-db ... --calibration-id <id>` で全行に `calibration_id`・`gain_db` が付く。`step19c --cut` は空の行を警告する

## 3. 採点（R02/R03）

- `step20_realsmoke_score_v3.py`: 通知規則は **v4.3（winner.json）＋警告音 hold** の正規実装。成功の窓 = [t_start − 1 s, t_cpa ＋ 1 s]
- 方向 = 注釈の窓（CPA の 2.5〜1.5 秒前）の**推定方位の中央**を 4 象限に丸めて注釈と比較（発火時刻の方位ではない）。
  分母は「全イベント（未検出は不一致）」と「推定があった例」の両方
- 前方 F は主要評価から除外して別集計（`--include-front` で含める）。履歴不足（クリップ内 CPA < 7.5 s）と多重車（n_car ≥ 2）も別集計
- 旧 `step20_realsmoke_score_v2.py`（v3.4 規則）は比較用に残す。報告では「v3.4（旧）」と明記

## 4. 機会枠（W8）

- `step19c --opportunity D=8`: D（サイレン等の遭遇枠）は上限目標。不足は情報表示のみで `--strict` でも不合格にしない。0 本のクラスは「未評価」と報告
