# v17 候補学習 — 装着高さをモデルの入力に与える — 事前宣言（2026-09-05 13:00・投入前）

本人判断（2026-09-05 12:41）「高さ入力で行きましょう」。目標（9/4）「マイクの高さが変わっても距離を当てられるモデル。その上で精度改善」。
**これは開発用の候補学習**（v15/v16 と同じ位置づけ）。確定評価（fold20・1 回）は 11 月の v2 で行い、ここでは使わない。

## 1. 根拠（統一採点器・v15 val 1,800 本・距離誤差 1 対 1）

| 高さの扱い | 距離誤差 | 意味 |
| --- | --- | --- |
| 固定 2.0〜2.1 m で学習・自分の高さで評価（v15b） | 7.8% | 高さが分かっているときの天井 |
| 幅 1.4〜2.1 m で学習（v15 / v16） | 10.3 / 9.9% | 高さを音から推定する代価 ≈ 2pt |
| 固定モデルを 20 cm 違う高さで使う | 20〜36% | 高さを間違えると崩れる |

機器は自分の装着高さを知っている（設定値 1 つ）。入力すれば、幅の頑健さを保ったまま天井に近づく余地がある。

## 2. 変更（v16 → v17）— モデルに高さの入力を足す。データ・ラベル・通知規則・学習レシピは v16 と同一

| # | 変更 | 中身 |
| --- | --- | --- |
| 1 | **高さの入力**（新） | クリップごとの mic_z（plan の値）を正規化 h = (z − 1.75) / 0.35 して MLP（1→64→2×特徴次元）に通し、HTSAT エンコーダ出力の特徴量に **FiLM**（特徴 × (1 + γ(h)) + β(h)）で掛ける。最終層はゼロ初期化 → 初期状態は無条件モデルと完全に同一（warm-start を壊さない） |
| 2 | **学習時のゆらぎ** | 入力する高さに N(0, 0.05 m) の雑音を足す（実用で ±5 cm の測り違いがあっても崩れないように） |
| 3 | 推論時 | plan の mic_z をそのまま入力（v12 val など plan に無いクリップは 1.5 m）。感度評価では ±0.20 m ずらして入力する |
| — | データ = v16（18,000 本）、水平距離ラベル、基準 100ep → 因果 ft v2 案（lr1e-4・REPEAT2・150ep）、ckpt 選択 = 統一採点器の距離誤差最小 | 不変 |

実装: `server_sde/height_patch.py`（sde_patch の後に適用するモンキーパッチ: データセットが mic_z を返す → Lightning の step が net に渡す → HTSAT_SDE_H が FiLM）。
起動 = `_train_sde17.py` / `_train_causal17.py` / `_infer_sde17.py`、因果推論 = `_causal_infer_v17.py`（v12 版のコピーに HEIGHT_* 環境変数と CAUSAL_GLOB を追加。v12 版は無変更）。
sbatch = `v17_smoke.sbatch`（ゼロ初期化で v16 と同一予測になることの確認＋学習の煙試験）→ `v17_train.sbatch` → `v17_causal.sbatch`（datasets_v16 を共用。生成は無し）。

## 3. 評価（先に固定）— 統一採点器（`scripts/_score_unified.py`）

- **主指標**: v15 val（v16 fold2 の mix≤9000・1,800 本・高さ 1.4〜2.1 m）で、**正しい高さを入力**したときの距離誤差（1 対 1）・至近捕捉（全 GT）・強到達・安全抑制。
  代表 ckpt = 距離誤差最小
- **副指標**: 高さ 3 帯ごと。交差 val（v12 fold2・1.5 m）。v16 fold2 全 3,600 本
- **感度（頑健性の本体）**: 代表 ckpt 付近（e099/e119/e139/e149）で入力の高さを **+0.20 m / −0.20 m** ずらして推論し、主指標の距離誤差を測る
- **判定**（比較相手 = v16 e139 9.9%、同じデータ・同じレシピ）:
  - 採用（v2 の土台候補にする）: 正しい高さで **v16 より 0.5pt 以上改善**（≤ 9.4%）、かつ **±0.20 m ずらしても v15（10.3%）より悪くならない**、かつ 強到達・抑制が v16 ±1.5pt 以内
  - 目標到達: 正しい高さで **9.4% 以下**（ft2 の水平換算値）。天井の目安は 7.8%
  - 改善なし（差 0.5pt 未満）: モデルは音から高さを既に推定できている、と読む。次は 3 高さ増量か、レシピ側（学習率・エポック）に戻る
  - 正しい高さでは良いがずらすと v15 より悪い: 入力への依存が強すぎる → ゆらぎを 0.10 m に増やして 1 回だけ再学習（それでも駄目なら不採用）
- 小差はシーン単位の対応付き区間推定（v16 と同じクリップで対にする）

## 4. 注意

- 対照は v16（同じデータ）。v16 との差だけが「高さ入力の効果」。更新回数は同じ（同じエポック・同じデータ）ので交絡なし
- 実用側: 装着時に地面からマイク中心までを 1 回測って設定に入れる（ヘルメット ≒ 身長＋15 cm、首元 ≒ 身長 − 35 cm）。歩行の上下動 ±3 cm はゆらぎで吸収
- 高さの正規化の中心 1.75 m・幅 0.35 m は学習範囲 1.4〜2.1 m の中心と半幅。範囲外（例 1.2 m）は外挿になるので、実用ではその旨を表示する
- 高さの表（plan）に無いクリップは 1.5 m 扱い。fold20 の確定評価 v2 のときは fold20 の高さを plan から与える（v2 の束で D13 を入れる前提）
