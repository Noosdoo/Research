## 3. 結論 — **60度は最適値ではない**

**山がない。単調なトレードオフ。** 広げるほど到達率が上がり、安全な車の抑制が下がる。

```
25° → 60°    至近 +5.1pt / 抑制 −1.7pt
60° → 90°    至近 +1.8pt / 抑制 −0.9pt
60° →180°    至近 +3.0pt / 抑制 −2.6pt
```

180°は連結の制約が実質ゼロ（どの方位でも連結される）。そこで至近到達が最大になることから、
**連結は「至近到達を犠牲にして抑制を買う」仕組み**だと分かる。狭めるほど、近い候補への
乗り換えが止まり、余計な至近発火が減る代わりに本物の至近も取り逃がす。

**したがって「60が最適」とは言えない。**言えるのは「**トレードオフ曲線上で選んだ点**」まで。

## 5. 中間発表では変えない

確定評価は **60°で1回だけ採点済み**（事前登録）。90°のほうが至近到達が高いと分かっても、
値を変えれば確定評価をやり直すことになり、枠組みに触る。**発表では60°のまま**とし、
「掃引して曲線を把握した」ことを述べるにとどめる。

変えるかどうかは中間発表後に、**抑制率をどこまで捨てられるか**（＝誤警告の許容量）を
決めてから判断する。→ [[project-post-seminar-todo]]

## 6. 実装上の落とし穴（再発防止）

`_notify_v4_eval.py` は **自分用に別の v4 を importlib で読み込む**
（`module_from_spec`＋`exec_module` は毎回新しいモジュールオブジェクトを作り、
`sys.modules` にも載らない）。そのため掃引側で別に読み込んだ v4 の
`track_series.__defaults__` を書き換えても**まったく効かず、全角度で同じ値が出る**。

**必ず `E.v4` を書き換えること。** 最初の実行はこれで12行すべて同一値になった。
`scripts/_sweep_link_deg.py` に注記とアサーションを入れてある。
