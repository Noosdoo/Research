## 現地に着いたら（2分）

### 立つ位置を決める

歩道の上、車道から**横2.0〜3.2m**の位置。ここが「鳴るべき車」の帯。
⚠️ 採点で使う横距離は縁石からではなく**対象の車の通過経路からマイクまで**（記録紙の `横距離m` もこれ）。3.2 m 付近の境界例は幅（例: 2.8〜3.5）で残し、別扱いにする（監査 R11）。
角のある場所なら、**塀の角から5〜10m**離れて立つ。

**⚠️ 三脚は立てない。** 設置物は道路使用の確認対象になりうる。身に着けて歩く受動観測は一般に対象外と考えているが、**装着＝一律不要とは断言しない**。地点ごとの実施形態（人数・反復・滞在時間）を記録し、判断の根拠を残す（監査 R14）。**運用（本人決定 2026-09-06）: 警察への事前の電話確認はせず、人の少ない早朝・夜に 1 人・歩行・設置物なしの受動観測で行う。**

### ヘルメットをかぶる

**マイク高さを測る（毎セッション・必須）**: かぶった状態で、地面からマイク中心までをメジャーで測り `session.csv` の `マイク高さ_cm` に書く（例 205）。
モデルはこの値を入力に使う（v17b・2026-09-06）。±10 cm 以内なら精度が保てるので、cm 単位でよい。

かぶったら、**協力者に見てもらうか鏡で、H3-VRの画面の水準器がセンターに来ているか確認する**。
H3-VRは傾きを表示するだけで補正はしない。頭の上なので自分では絶対に見えない。

→ `session.csv` の `水準器OK` に `y` を書く。

## 儀式（60秒・セッション冒頭に1回だけ）

ここから録音を回す。**地点を移動しても、ヘルメットを脱がない限りやり直さなくてよい**。

### 騒音計と並べて、無言で60秒

**何のため**: 録音の数字を「実際に何デシベルだったか」に換算する基準を取る。
LAeqは**60秒ぜんぶを1つの数字にしたもの**（1秒ごとの平均ではない）なので、
60秒押して出た値を1つ書けばよい。

- 騒音計と H3-VR を近くに置く
- **60秒間、一言もしゃべらない**（声が入ると平均が汚れる）
- 60秒たったら騒音計の読み値を `session.csv` の `LAeq_dB` に手打ち
- 校正は**別ファイル**（録音ボタン → 60 秒 → 停止）。騒音計を回した 60 秒 ＝ そのファイル全長なので `暗騒音区間_秒` は **`0-60`**（帰宅後の step19 も全長を使う）。
  ファイルの途中の 60 秒を測ったときだけ、その区間（例 `10-70`）を書き、帰宅後に `--laeq-window 10-70` を渡す（記録と json が違うと切り出しが止まる・再監査2 Q02）
- **ゲインを変えたら、新しいセッション（session_id を増やす）として校正からやり直す**。同じセッション内で校正を 2 つ持たない（再監査2 Q02）

**⚠️ 計測中の発声は禁止。** これを守らないと較正がやり直しになる。

### 校正の点検 — 指パッチン 4 方位（初日）／前 1 打（2 日目以降）（2026-09-06・監査 R09）

**何のため**: 「マイクの前＝自分の前」「右は右」であることを確かめる。正面 1 打だけでは左右反転や軸の取り違えを見逃すので、初日は 4 方位。

**音は指パッチンでよい**（手拍子でも可）。片手で済むので後ろにも出しやすい。腕を伸ばした先（約 0.6 m）・耳の高さで鳴らす。

**押すボタンと順番**（校正 60 秒の録音を止めたあと、**別のテイクとして**録る。校正ファイルは無音のままにするため）:

1. H3-VR の **録音ボタンを押す**（これが点検テイク。ファイル名を `session.csv` の `点検原本` に書く）
2. 立ったまま正面を向いて動かない。**前**に腕を伸ばして 1 回パチン → 1 秒待つ
3. **右**に腕を伸ばして 1 回 → 1 秒待つ
4. **後ろ**（頭の後ろに手を回す）で 1 回 → 1 秒待つ
5. **左**に腕を伸ばして 1 回
6. **録音ボタンを押して止める**。しゃべらない。全部で 10 秒ほど

**帰宅後**: `python scripts/step19e_check_azimuth.py --in raw/<点検原本>` を実行する。4 打の方位を読み、
**前 0 / 右 −90 / 後 180 / 左 +90（左が＋）** の並びかを判定し、取り違え（左右反転・前後反転・XY 入れ替わり）を言い当てる。
正面の値を `session.csv` の `正面ズレ_deg` に**そのまま**書く。10° を超えると道具が `--yaw` の値を出すので、step19b にそれを渡す。

**2 日目以降は前 1 打だけ**: `--expect 前` で同じ道具にかける。ヘルメットをかぶり直した後・角度をいじった後は必ず。

### 録音とストップウォッチを同時に開始する

**車が来る気配がしたら、録音ボタンとストップウォッチを同時に押す。** そのまま無言で待つ。

- H3-VRのボタンは**頭の上にあって見えない**ので、手探りで押すことになる。
  **買ったら何度か練習しておく**
- 同時に押すので、録音の時刻とラップの時刻はそろう

### 車が通り過ぎるまで、ただ立っている

- **一言もしゃべらない**
- 動かない。姿勢を変えない
- **正面を向いたまま**（ヘルメットなので、頭を動かすとマイクの向きが変わる）

### 車の前端が真横（肩の線）に来たら、ラップを押す

指1本で押せる。**押した値がそのまま `ラップ秒` になる。**

**⚠️ ラップの役割は「波形のどの山がどのイベントか」を特定することだけ。**
最接近の時刻は「真横で音量が最大」で読めることが多いが、**音量最大＝最接近ではない場合がある**（加速・警告音・反射・別の車。監査 R05）。
最接近時刻の正解は**ラップ**で取る（本人決定 2026-09-06 03:45・目印も予備試験も不要）: **車の前端（バンパー）が自分の真横＝肩の線を通った瞬間**に押す。
押すまでの反応時間は測らない（本人決定）。**正解の時刻は「前端が肩の線を通ったのを見て押した時刻」そのもの**と定義し、物理的な最接近との細かな秒差の一致は主張しない。
リード（最接近 − 通知）はこの時刻基準の指標。前端基準なので車の中央の通過より早い側にずれる（例: 車長 4.5 m・徐行 1 m/s なら 2 秒ほど。上限ではなく構成例。大型・低速ほど大きい）（再監査 N07・再監査2）。
音量最大の時刻で正解を決めない（波形は「どの山がどのイベントか」の確認だけに使う）。

**クラスごとの「ラップを押す瞬間」（2026-09-06 03:55 確定）**

| クラス | ラップを押す瞬間 | 採点で使う時刻 | 象限に書く向き |
| --- | --- | --- | --- |
| 車 car_drive | **前端（バンパー）が肩の線を通った瞬間** | 最接近 = ラップ | 最接近の 2.5〜1.5 秒前の向き |
| キックボード kick | 乗っている人の体が肩の線を通った瞬間 | 同上 | 同上 |
| バイク bike | 前輪が肩の線を通った瞬間 | 同上 | 同上 |
| サイレン siren | **音が始まった（気づいた）瞬間**。救急車が通り過ぎても押し直さない（通過は特記に「通過 ○秒」） | 始まり = ラップ、成功窓は ラップ−1〜＋4 s | 音が始まったときの向き |
| クラクション horn | 鳴った瞬間 | 同上 | 鳴った車の向き |
| バック音 backup_beep | ピーピーが始まった瞬間 | 同上 | 向き |
| 自転車のベル bike_bell | 鳴った瞬間 | 同上 | 向き |
| 踏切 crossing | 警報が鳴り始めた瞬間。**録音開始時にすでに鳴っていたら ラップ=0 と書き、特記に「開始時から鳴動」** | 同上 | 警報機の向き |
| 何もなし none | 押さない | — | — |

距離クラス（車・キック・バイク）は「一番近づいた瞬間」、警告音クラスは「鳴り始め」がラップ。前者は通知が最接近の何秒前に出たか（リード）、
後者は鳴り始めから何秒で通知が出たか（遅れ）を測る。

### 車が通り過ぎたら、5秒数えてから録音を止める

**⚠️ すぐ止めない。**

解析に使う10秒は「最接近の8秒前〜2秒後」で切り出す。
最接近から3秒以内に音を立てると、**それがクリップに入り、解析から除外＝1本失う**。

| take_id | 3 | **210本を数える単位**。録音1回につき1つ増える |
| event_id | 1 | そのテイクの中の何番目か |
| class | car_drive | 8クラス＋none |

| **n_car** | 1 | **音が重なっている台数** |
| 車種 | ガソリン | EVは静かなので層別で見る |
| 速度 | 徐行 | 目視3段（徐行／約20／約30） |

### ⚠️ 象限は「マイク基準・最接近の2.5〜1.5秒前」

- 自分の体がどっちを向いていたかは**記録しない**。ヘルメットなので
  「マイクの正面＝自分の正面」で、それは初日に1回確かめてある
- **真横に来た瞬間ではなく、その1.5〜2.5秒前**の向きを書く。
  **方向を比べる時点**として固定した窓。通知の成功の窓 [イベント開始−1 s, 最接近＋1 s] とは別物。採点器 v3（`step20_realsmoke_score_v3.py`）はこの窓の推定方位の中央を 4 象限に丸めて注釈と比べる（2026-09-06 監査 R03 で訂正）

### ⚠️ 複数台が重なったら（2026-09-06・1 車両 1 行に変更＝監査 R06）

| 状況 | 書き方 |
| --- | --- |
| 走行音が**少しでも重なっている** | **車両ごとに行を分け**、同じ `overlap_group_id`（G1…）と `n_car`（群の台数）を付ける。各行にその車両のラップ・象限・横距離 |

## 帰宅後、その日のうちに（半日）

**溜めない。** 翌日に持ち越すと、記録の意味が思い出せなくなる。

（一本の規則 = `md/design/実録_解析パイプライン_現場CSVから採点まで_2026-09-06.md`。2026-09-06 監査 R01/R04 で経路を直した）

1. **現場 CSV → 解析入力**: `python scripts/step19d_field_csv_to_ann.py --session session.csv --events events.csv --out ann_orig.csv --audio-dir raw/`
   （session×take を一意キーに、象限→quadrant、t_cpa = ラップ秒、t_start = t_cpa − 6 s の規則、校正 id を付ける。結合だけでは列が足りない）
2. **校正録音から補正量を 1 回だけ求める**: `python scripts/step19_realsmoke_convert.py --in raw/ --calib raw/<校正原本（例 ZOOM0001.wav）> --laeq 52.3 --gain-only --out out/realsmoke/conv`（ノートの「出力」タブがセッションの値入りで出す）
   （校正の 60 秒は別ファイル。**`--laeq-window` は省略＝校正ファイル全長**。騒音計で測った 60 秒と音声の 60 秒を同じ区間にする（再監査 N04）。セッションごとに 1 回ずつ実行し、`calibration_<校正原本の stem（例 ZOOM0001）>.json` ができる。校正 id = 校正原本の stem（2026-09-06・H01））
3. **10 秒クリップに切り出す**: `step19b_realsmoke_cut.py --mode event --in raw/ --ann ann_orig.csv --calib-dir out/realsmoke/conv --pitch/--roll/--yaw ...`（各原本の校正 id から補正量を引く。2 セッションを同じフォルダで処理しても取り違えない。
   注釈の無い原本・原本の無い注釈があれば止まる。最接近が 8 秒地点。
   録音開始が遅く CPA 前の履歴が足りないテイクは `history_short=1` が付き、主要評価から外れる）
4. **step19c 検査器を通す**: `--cut --subplan "D:crossing=8,backup_beep=4,horn=4,siren<=4"`（校正 id・session×take の一意性・none 行の書き忘れ・D の内訳。サイレンだけが 0〜4 本の機会枠で、踏切 8・バック音 4・クラクション 4 は必須）
5. **採点は v3**: `step20_realsmoke_score_v3.py`（v4.3＋hold。前方 F・履歴不足・多重車は別集計）

⚠️ **実録は学習には使わない。** 学習は合成データだけで、実録は
「合成で学習したモデルが実環境でどこまで通用するか」を測る**評価用**。

| H3-VR | 全部。前日に設定、本番で録音ボタン |
| SDカード・電池 | 前日にセット。予備は現地で交換 |
| 風防 | 前日に装着。外さない |
| ヘルメット＋マウント＋アダプター | 前日に組む。現地でかぶる |

| メジャー・コーン | **公道では使わない**。私有地の統制試行だけ |
| バックブザー・キックボード | D区分・E区分の日だけ。A区分の車では使わない |
