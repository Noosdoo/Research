## スマホで記録する（ヘルメット収録ノート・2026-09-06）

紙や CSV に直接書く代わりに、同じフォルダの `ヘルメット収録ノート.html`（スマホのブラウザで開く 1 枚のページ）で記録できる。
流れの案内（校正 60 秒の秒読み・指パッチンの方位案内）、テイクと事象の追加（ラップは**純正ストップウォッチ**の分・秒を写す）、クラス・象限・車種などの**選択式ボタン**、
原本ファイル名の自動採番（取り消しは「録音していない／負例として残す／除外して次へ」の 3 択で番号を合わせる。除外は備考「除外: …」に残り、切り出しから外れる）、
出力タブの**未処理一覧**（閉じていないテイク・事象 0 件が片づくまでコピーを止める）、最後に session.csv / events.csv と**同じ列順**のテキストと、
セッションの値入りの**帰宅後コマンド**を「コピー」または「共有」で PC に送る。記録は端末のブラウザに残る。監査対応は [レビュー対応](../../audit/ヘルメット収録ノート_レビュー_対応_2026-09-06.md)。
公開版（claude.ai の非公開ページ）も同じもの。CSV の列の意味は以下のとおり。

### ⚠️ 象限の定義（2026-09-05に確定）

- **マイク基準**。自分の体がどっちを向いていたかは記録しない
  （ヘルメット装着なので「マイクの正面＝自分の正面」で、ズレは初日に確認済み）
- **最接近の2.5〜1.5秒前**の向きを書く。真横に来た瞬間ではない
  （**方向を比べる時点**として固定した窓。通知の成功の窓 [イベント開始−1 s, 最接近＋1 s] とは別物。採点器 v3（`step20_realsmoke_score_v3.py`）はこの窓の推定方位の中央を 4 象限に丸めて注釈と比べる（2026-09-06 監査 R03 で訂正））

**例**: 右後ろから来て自分の右を追い抜いていく車は、2秒前の時点ではまだ**後ろ寄り**。
真横に来た瞬間で判断すると `R` と書きたくなるが、**方向を比べる窓（2.5〜1.5 秒前）では `B`** になる。
迷ったら「**ラップを押す2秒前、音はどっちから聞こえていたか**」で決める。

### ⚠️ ラップを押す瞬間はクラスで違う（2026-09-06 確定）

**クラスごとの「ラップを押す瞬間」（2026-09-06 03:55 確定）**

| クラス | ラップを押す瞬間 | 採点で使う時刻 | 象限に書く向き |
| --- | --- | --- | --- |
| 車 car_drive | **前端（バンパー）が肩の線を通った瞬間** | 最接近 = ラップ | 最接近の 2.5〜1.5 秒前の向き |
| キックボード kick | 乗っている人の体が肩の線を通った瞬間 | 同上 | 同上 |
| バイク bike | 前輪が肩の線を通った瞬間 | 同上 | 同上 |
| サイレン siren | **音が始まった（気づいた）瞬間**。救急車が通り過ぎても押し直さない（通過は特記に「通過 ○秒」） | 始まり = ラップ、成功窓は ラップ−1〜＋4 s | 音が始まったときの向き |
| クラクション horn | 鳴った瞬間 | 同上 | 鳴った車の向き |
| バック音 backup_beep | ピーピーが始まった瞬間 | 同上 | 向き |
| 自転車のベル bike_bell | 鳴った瞬間 | 同上 | 向き |
| 踏切 crossing | 警報が鳴り始めた瞬間。**録音開始時にすでに鳴っていたら ラップ=0 と書き、特記に「開始時から鳴動」** | 同上 | 警報機の向き |
| 何もなし none | 押さない | — | — |

距離クラス（車・キック・バイク）は「一番近づいた瞬間」、警告音クラスは「鳴り始め」がラップ。前者は通知が最接近の何秒前に出たか（リード）、
後者は鳴り始めから何秒で通知が出たか（遅れ）を測る。

### ⚠️ 前から来たイベントも1行書く（2026-08-30決定）

採点では別集計にするが、**録らなければ二度と取れない**。

**例**: 正面から対向車が来て通り過ぎた → `class=car_drive, 象限=F` で1行書く。
「研究の対象外だから書かなくていい」ではない。

### ⚠️ 複数台の書き分け（2026-09-06・1 車両 1 行に変更＝監査 R06）

| 状況 | 書き方 | 例 |
| --- | --- | --- |
| 走行音が**少しでも重なっている** | **車両ごとに行を分け**（event_id を増やす）、同じ `overlap_group_id`（`G1`…）を付け、`n_car` に群の台数 | 先行車の音が消える前に後続が入ってきた → 2 行・G1・n_car=2 |
| 明らかに**離れている** | 別の行（event_id を増やす）。`overlap_group_id` は空欄 | 1台目が完全に去って5秒静かになってから2台目 |

各行には**その車両**のラップ秒・象限・横距離を書く。どの車への通知か決められない例は特記に「群のどれか」と書く。
採点は「車両単位」を主、「群のいずれかへの通知」を別集計にする（n_car≥2 の行は主要評価から分ける）。

## 帰宅後

（一本の規則 = `md/design/実録_解析パイプライン_現場CSVから採点まで_2026-09-06.md`）

1. **現場 CSV → 解析入力**（結合ではなく変換）

   ```
   python scripts/step19d_field_csv_to_ann.py --session session.csv --events events.csv --out ann_orig.csv --audio-dir raw/
   ```

2. **校正録音（別ファイル・60 秒）から補正量を 1 回だけ求める**。本番テイクに `--laeq-window 10-70` を渡すと停止する（25 秒しかない）

   ```
   python scripts/step19_realsmoke_convert.py --in raw/ --calib raw/<session>_calib.wav --laeq 52.3 --gain-only --out out/realsmoke/conv
   # --laeq-window は省略＝校正ファイル全長（騒音計で測った 60 秒と同じ区間・再監査 N04）。セッションごとに実行
   ```

3. **10 秒クリップに切り出し**: `step19b --mode event --in raw/ --ann ann_orig.csv --calib-dir out/realsmoke/conv --pitch/--roll/--yaw`（校正は各原本の id から自動で引く。CPA 前の履歴が足りないテイクは `history_short=1`）
4. **step19c 検査器を通す**（`--cut --subplan "D:crossing=8,backup_beep=4,horn=4,siren<=4"`。列・校正 id・session×take の一意性・none 行の書き忘れ・D の内訳）
5. **採点は `step20_realsmoke_score_v3.py`**（v4.3＋hold。象限は上の窓の推定方位と比べる。前方 F は別集計）

⚠️ **実録は学習には使わない（設計判断。「使えない」ではない）。** 学習は合成データだけで、実録は
「合成で学習したモデルが実環境でどこまで通用するか」を測る**評価用**。
