# 当日スマホで書き込む表（2026-09-05）

`実録_記録紙テンプレート_2026-09-01.md` の紙版を、**スマホのスプレッドシートで
埋められる形**にしたもの。列は注釈CSV（step19c検査器の BASE_COLS）へそのまま
転記できるように揃えてある。

| ファイル | 単位 | いつ書く |
| --- | --- | --- |
| `session.csv` | 1セッション=1行 | **その日の最初に1回** |
| `events.csv` | 1イベント=1行 | **イベントのたび** |
| `例_記入済み.csv` | — | **書かない。迷ったときに見る**（下の記入例と同じ中身） |

**使い方**: 2つとも Google スプレッドシート（or Excel）で開き、
`events.csv` を開きっぱなしにして現場で埋める。1行目は記入例なので消す。

---

## ID の意味（ここを取り違えると全部ずれる）

| | 意味 | 例 |
| --- | --- | --- |
| **session_id** | 1回の外出＝儀式1セット | `20260920_A1` |
| **take_id** | **録音ボタンを押して止めるまで**で1つ。**210本はこれを数える** | 1, 2, 3, … |
| **event_id** | そのテイクの中の何番目か | 1テイクに車2件＋サイレン1件なら 1,2,3 |
| clip_id | 帰宅後に切り出す10秒クリップの番号 | **当日は書かない**（スクリプトが振る） |

`t_start` / `t_cpa` も**当日は書かない**。波形と `ラップ秒` から帰宅後に決まる。

## events.csv の列

| 列 | 書き方 | 記入例 |
| --- | --- | --- |
| **session_id** | `session.csv` と同じ値 | `20260920_A1` |
| **take_id** | 録音1回につき1つ増やす | `3` |
| **event_id** | そのテイク内の連番。ふつうは `1` のまま | `1` / `2` |
| **class** | `siren` `horn` `backup_beep` `bike_bell` `car_drive` `crossing` `kick` `bike` `none`(負例) | `car_drive` |
| **象限** | `F` 前 / `R` 右 / `B` 後 / `L` 左。**マイク基準・最接近の2.5〜1.5秒前**の向き | `R` |
| **ラップ秒** | ストップウォッチのラップ。**押した瞬間の値をそのまま** | `8.4` |
| **n_car** | **音が重なっている台数**。重なっていれば1行にまとめる | `1` / `2` |
| **車種** | `ガソリン` `EV` `HV` `大型` `不明`。EVは静かなので層別で見る。**車以外は空欄** | `ガソリン` |
| **速度** | `徐行` `約20` `約30`（目視3段）。**車以外は空欄** | `徐行` |
| **横距離m** | 公道は目測の概数でよい。私有地の統制試行だけ実測 | `2.0` |
| **状態** | `静止` / `歩行` | `静止` |
| **pair_id** | **歩行対比のときだけ**。同条件の静止/歩行に同じ値。それ以外は空欄 | `P1` |
| **特記** | 会話が入った／風が強かった／自信がない、など | `後続と重なる` |

### ⚠️ 象限の定義（2026-09-05に確定）

- **マイク基準**。自分の体がどっちを向いていたかは記録しない
  （ヘルメット装着なので「マイクの正面＝自分の正面」で、ズレは初日に確認済み）
- **最接近の2.5〜1.5秒前**の向きを書く。真横に来た瞬間ではない
  （通知層の判定窓がここなので、採点の窓と一致させる）

**例**: 右後ろから来て自分の右を追い抜いていく車は、2秒前の時点ではまだ**後ろ寄り**。
真横に来た瞬間で判断すると `R` と書きたくなるが、**判定窓では `B`** になる。
迷ったら「**ラップを押す2秒前、音はどっちから聞こえていたか**」で決める。

### ⚠️ 前から来たイベントも1行書く（2026-08-30決定）

採点では別集計にするが、**録らなければ二度と取れない**。

**例**: 正面から対向車が来て通り過ぎた → `class=car_drive, 象限=F` で1行書く。
「研究の対象外だから書かなくていい」ではない。

### ⚠️ 複数台の書き分け

| 状況 | 書き方 | 例 |
| --- | --- | --- |
| 走行音が**少しでも重なっている** | **1行にまとめて `n_car=2`** | 先行車の音が消える前に後続が入ってきた |
| 明らかに**離れている** | **別の行**（event_id を増やす） | 1台目が完全に去って5秒静かになってから2台目 |

秒数の閾値は設けない。採点は「そのイベントで通知が出たか」なので、
重なっている2台を分けても、どちらへの通知か区別できないため。

**n_car は必ず書く。** 多重車は性能が落ちる層（2台69.7% / 3台34.8%）なので、
ここで層別が効く。

## 帰宅後

1. `session.csv` の `LAeq_dB` と `暗騒音区間_秒` を step19 に渡して**絶対較正**

   ```
   python scripts/step19_realsmoke_convert.py --in raw/take01.wav \
       --laeq 52.3 --laeq-window 10-70
   ```

2. 波形と `ラップ秒` から `t_cpa` を決めて**10秒クリップに切り出し**
3. この2ファイルを結合して `ann_orig.csv` にする
4. **step19c検査器を通す**（列の不一致・none行の書き忘れを機械的に見つける）

⚠️ **実録は学習には使わない。** 学習は合成データだけで、実録は
「合成で学習したモデルが実環境でどこまで通用するか」を測る**評価用**。
