## 1. ひとことで

これまでの通知は「**いま何メートル先か**」だけで鳴らしていました。
これを「**このまま進むと、あと何秒後に、どこまで近づくか**」で鳴らすように変えました。

たとえるなら、踏切の前で「もう電車が目の前だ」と気づいてから警報を鳴らすのをやめて、
「この速さなら12秒後にここを通る」と分かった時点で鳴らす、という違いです。

結果（valの1,358クリップ・GTイベント2,115件）:

| 指標 | v3.4（距離だけ） | **v4.1（最接近予測）** | 変化 | 有意性 |
| --- | --- | --- | --- | --- |
| 至近（重大）に鳴った割合 | 91.3% | **95.5%** | +4.2pt | p<0.0001 |
| 注意に鳴った割合 | 84.9% | **92.0%** | +6.9pt | p<0.0001 |
| 安全な相手に鳴らさずに済んだ割合 | 82.1% | **74.3%** | **−7.7pt** | p<0.0001 |
| 通知から最接近までの余裕（中央値） | 0.20s | **1.50s** | **+1.30s** | — |
| 余裕が2.5秒以上あった割合 | 4.1% | **26.7%** | **+22.6pt** | — |
| どのイベントにも紐づかない発火 | 736 | **1,346** | +610 | — |

有意性は**対応のあるMcNemar検定**（同じイベントで新旧を比べる）。到達側は
**v3.4が鳴らせたイベントの取りこぼしがゼロ**（旧だけ成功0件 / 新だけ成功25件）。
抑制側は逆に**一方的に悪化**（旧だけ成功62件 / 新だけ成功1件）。
つまり v4.1 は構造上「v3.4の発火をすべて含み、そこに早い通知を足したもの」である。

車では 0.20s → **1.70s**、バイクでは 0.10s → **1.40s**、
キックボードは 0.50s → 0.80s。**速い相手ほど大きく効く**という設計の狙いどおりです。

**代償は正直に書きます。** 安全な相手への抑制が 7.7pt 落ち、紐づかない発火が
8割増えました。「早く鳴らす」と「余計に鳴らさない」は原理的に両立しません。

## 2. なぜ変えたか

中間発表で松澤先生から
「ファインチューニングして終わりにするなら、もっと工夫を。
たとえばトラックが来る3秒前に検知できても使えない、そこを工夫するとか」
という指摘を受けました。

v3.4 の規則は

```
if d <= 1.5: 強 / elif d <= 3.2: 中 / else: 鳴らさない
```

で、**速度をまったく見ていません**。この規則の弱点は構造的です。
時速50km（14m/s）の車が近づくとき、3.2m の線を越えてから最接近までは
0.2秒しかありません。つまり**相手が速いほど余裕が短くなる**。
実測でも車のリード中央値は 0.20 秒でした。指摘のとおり、これでは使えません。

## 3. 最初の案（v4: 到達時間 TTC）は失敗した

まず「接近速度 v を推定して、危険域に入るまでの時間 TTC=(d−r)/v で鳴らす」を
実装しました（`fires_ttc`）。結果:

| 指標 | v3.4 | v4(TTC) |
| --- | --- | --- |
| 至近到達 | 91.3% | 99.0% |
| **安全抑制** | **82.1%** | **15.7%** |

**安全抑制が 82.1% → 15.7% に崩壊**し、使い物になりませんでした。

原因ははっきりしています。TTC は「**近づいているか**」しか見ません。
横を5m離れてすれ違う車も、正面から来る車も、近づいている間は同じ扱いになります。
実際の軌跡を見ると、GTの音源は方位が中央値166度も振れており（＝ほとんどが
「横を通り抜ける」動き）、そのほぼ全部に鳴っていました。

**この失敗自体が知見です。** 接近速度だけでは不十分で、**進行方向**が要る。

## 4. v4.1: 最接近距離を予測する

相対位置 r（大きさ d）と相対速度 v を、動径成分 ḋ と接線成分 d·ȧ に分けます
（ȧ は方位の変化率 [rad/s]）。等速直線運動を仮定すると

```
|v|²    = ḋ² + (d·ȧ)²
t_cpa   = −(r·v)/|v|²  = −d·ḋ / |v|²      … 最接近する時刻
d_cpa   = |r×v|/|v|    = d²|ȧ| / |v|      … そのときの距離
```

鳴らす条件（**2本の独立した列**の論理和。確認フレーム数が別なのが要点）:

```
強 = 予測列: d_cpa ≤ CPA_STRONG_M かつ t_cpa ≤ TTC_WARN   が CONFIRM_CPA(4) 連続
   ∪ 保険列: d ≤ T3                                      が CONFIRM(2) 連続
中 = 予測列: d_cpa ≤ CPA_MID_M    かつ t_cpa ≤ TTC_CAUTION が CONFIRM_CPA(4) 連続
   ∪ 保険列: d ≤ SUPP                                     が CONFIRM(2) 連続
```

距離しきい値は捨てず**保険**として残します（速度が測れないほど検出が途切れる場合や、
既に危険域内にいる場合に効く）。**保険列の確認フレーム数を v3.4 と同じ2に保つことが重要**で、
ここを4にすると v3.4 より0.2秒遅れて鳴る事故が起きます（§6-bis）。
この構成により、v4.1 の発火は **v3.4 の発火を必ず含みます**。
強/中は v3.4 と同じく独立した列で数え、
同一エピソード内に強があれば強へ昇格する規約もそのままです。

単体テスト（`scripts/test_notify_v4_units.py`・15項目全合格）のうち中心は3つ:

- **V9**: 幾何の検算。20m先を14m/sで正面 → 予測最接近 0.000m、
  5m横をすれ違う軌跡 → 予測最接近 5.000m
- **V10**: 正面に来る相手には 20.2m 手前で鳴る
- **V11/V12**: 5m横を通り過ぎるだけの相手には**鳴らない**。
  同じ軌跡を旧TTC規則に通すと鳴る（＝v4.1で直したことの回帰テスト）

## 5. しきい値の決め方（出来レースにしないための手順）

> **この節は「欠陥を直す前」の構造での選定記録です。** 直したあとに同じ手続きを
> かけ直すと選択が安定しなくなりました（→ §6-bis）。しきい値はこの節で選んだ値を
> 据え置いています。同じデータで選び直すと出来レースになるためです。

しきい値を val で選んで同じ val で成績を出すと出来レースになります。そこで:

1. val の 1,358 クリップを**クリップ名末尾番号の偶奇**で2分割（A 673本 / B 685本）
2. 選び方の方針を**先に2つだけ**決める
   - 安全重視 = 抑制がv3.4以上・重大到達がv3.4−1pt以内 の中でリード最大
   - リード重視 = 抑制がv3.4−5pt以内・重大到達がv3.4以上 の中でリード最大
3. 216通りを探索し、**Aで選んでBで採点／Bで選んでAで採点**の両向きを実施

結果（`out/notify_v4_1_2026-08-18/holdout_tuning.txt`）:

| 方針 | Aで選ぶ | Bで選ぶ | 再現したか |
| --- | --- | --- | --- |
| 安全重視 | (5,1.0,2.0,2.5,4.0,10,4) | (5,0.7,1.5,2.5,4.0,30,4) | **✗ 別設定・Bの選択はAで抑制割れ** |
| **リード重視** | (5,1.0,2.0,2.5,4.0,30,4) | **同じ設定** | **✓ 両向きで同じ改善量** |

リード重視は**両方の分割から独立に同じ設定が選ばれ**、ホールドアウトでも
（Aで選びBで採点）重大+0.7 注意+7.0 安全−4.1 リード+1.40s、
（Bで選びAで採点）重大+1.3 注意+3.4 安全−3.2 リード+1.30s と再現しました。
安全重視は再現しなかったので採りません。

**採用値**: `VEL_WIN=5, CPA_STRONG_M=1.0, CPA_MID_M=2.0, TTC_WARN=2.5,
TTC_CAUTION=4.0, D_MAX_TTC=30.0, CONFIRM_CPA=4`

なお `T3=1.5 / SUPP=3.2` は**GT側の危険区分の定義**なので動かしていません
（鳴らす側のしきい値だけを `CPA_STRONG_M / CPA_MID_M` として分離した）。

## 5-bis. しきい値の根拠（2026-08-18 に一次資料で確認）

| 定数 | 値 | 根拠 |
| --- | --- | --- |
| T3（重大の距離境界） | 1.5m | 改正道交法（2026/4施行）の車→自転車の側方間隔「1m程度・1.0〜1.5m目安」を**借用**。自転車→歩行者の明文数値は存在せず**仮定**と明記済み。評価シナリオの危険3層(0.5-1.5 / 1.5-3 / 3-15m)の境界としても一貫使用 |
| TTC_WARN | 2.5s | **AASHTO Green Book pp.111-113** の知覚反応時間。全ドライバーの90パーセンタイルを上回る値。一次データは Johansson & Rumar (Human Factors 13(1), 1971)：制動を予期した321名で平均0.66秒・約10%が1.5秒以上・予期しない場合+約1.0秒。**車載前方衝突警報も TTC 2.6秒**（Kiefer et al., NHTSA DOT HS 809 574）で同程度 |
| TTC_CAUTION | 4.0s | **Vogel (2003), Accident Analysis & Prevention 35(3):427-433** — TTC<4秒は危険な状況を示す |
| SUPP / T2 | 3.2m / 3.0m | **外部根拠なし**。3層サンプリングの上限3mと、境界揺れ用の緩衝0.2m |
| CPA_STRONG_M / CPA_MID_M | 1.0m / 2.0m | **外部根拠なし**。探索で決めた設計値。**危険度の定義(1.5m/3.2m)より厳しい**ので、「1.5m以内に来る車に鳴らす」と説明すると実装と食い違う |
| VEL_WIN / CONFIRM / CONFIRM_CPA / D_MAX_TTC / V_MIN / LINK_DEG / AZ_MATCH | 5fr / 2fr / 4fr / 30m / 0.5m/s / 60° / 25° | 工学的選択 |

**2.5秒の扱いに注意。** これは「自動車を運転中で、制動を予期している人」の反応時間である。
歩行中の難聴者が振動通知を受ける場面にそのまま当てはまる保証はない。
第7回監査（2026-07-28）の裁定どおり **「理想線」** として扱い、安全保証値として書かない。

**訂正**: 従来「リードタイム最低線2.0s」の根拠に挙げていた PubMed 20945247 は、
実体が**英国の聴覚障害者の道路安全に関する調査**（Hersh, Ohene-Djan & Naqvi, 2010）であり、
回避時間の測定研究ではなかった。**2.0秒という最低線には裏付けが無い**。
（この文献自体は研究の前提を支える良い資料なので、関連研究側へ移す）

## 6. 天井はどこか — 誤差源の切り分け

「リード1.50秒」で止まっているのは規則が悪いのか、推定精度が足りないのか。
GTの1トラックだけを追った系列に規則を当て、入力を段階的に正解値へ差し替えて
測りました（`scripts/_notify_v41_oracle.py`・イベント1,846件）。

**安全抑制をその水準に保ったまま出せるリード中央値[秒]**:

| 入力の条件 | 距離規則 | 抑制100% | 98% | 95% | 90% | 85% |
| --- | --- | --- | --- | --- | --- | --- |
| GT距離 + GT方位（完璧） | 0.20 | **2.20** | 2.80 | 3.00 | 3.10 | 3.10 |
| GT距離 + 推定方位 | 0.20 | − | − | 1.60 | 2.00 | 2.30 |
| 推定距離 + GT方位 | 0.20 | − | − | − | − | 1.95 |
| 推定距離 + 推定方位 | 0.20 | − | − | − | − | 1.70 |

（− はその抑制率を満たす設定が存在しない）

読み取れること:

1. **規則の設計は正しい。** 入力が完璧なら、重大到達100%・安全抑制100%を保ったまま
   リードが 0.20 → **2.20秒**（抑制を95%まで緩めれば3.00秒）
2. **最大のボトルネックは距離推定。** 方位だけが誤差なら抑制95%を保てるのに、
   距離が誤差になると抑制90%すら満たせない
3. 実装のままの 1.50秒 と、対応付けを正解にした 1.70秒 の差は
   **複数音源の追跡（どの検出がどの車か）**の損失

補足: 検知そのものは天井ではありません。重大イベントの **81.4%** は
最接近の2.5秒以上前から検知できています（初検知→最接近の中央値 4.80秒）。
**鳴らせるのに鳴らしていない**状態であり、伸ばす余地があるということです。

## 6-bis. 自己監査で見つけたもの（2026-08-18・`scripts/_notify_v41_audit.py`）

**修正した欠陥**: 距離保険（近距離で無条件に鳴らす部分）にまで確認4フレームを課していたため、
**v3.4より0.2秒遅れて鳴っていた**。v3.4が捕まえた至近イベント14件を取りこぼしていた。
保険は確認2（v3.4と同じ）、最接近予測だけ確認4に分離して解消
（v3.4よりリードが悪化したイベントが **17.6% → 2.1%**）。

**検証して問題なしと確認した近似**

| 疑い | 検証方法 | 結果 |
| --- | --- | --- |
| 仰角を無視してよいか | 3Dの角速度で計算し直す | 至近95.5で同じ・抑制+0.5pt。**無害** |
| 距離はj時点・傾きは窓の中心時点という時刻ずれ | 最小二乗直線をjで評価した値に揃える | 至近95.5で同じ。**無害** |
| 採点の貪欲マッチングの順序依存 | イベントを時刻順に処理し直す | 2,115件中8件のみ変化。**無害** |
| 偶奇分割の偏り | 2群の危険区分の比率を比較 | 1pt以内。**無害** |

**残る宿題**: 「紐づかない発火」1,346件のうち、最接近を過ぎてからの鳴り続けが約23%、
**残り約1,000件は真に紐づかない発火**（v3.4は512件）。ここは未分析。

**しきい値の選び直しについて**: 上の欠陥を直すと、§5の手続きで**両分割から同じ設定が
選ばれなくなった**（安全重視は候補なし、リード重視は分割ごとに別設定）。
同じデータで選び直すと出来レースになるため、**しきい値は欠陥修正前に選んだ値のまま据え置いた**。
本番の選定は実録データが揃ってから、事前登録し直して行う。

## 7. 卒論に書けること

1. 距離しきい値だけの通知は、**相手が速いほど余裕が短くなる**（車で0.20秒）
2. 接近速度（TTC）を入れるだけでは**逆効果**。横を通り過ぎる相手に鳴り、
   安全抑制が82.1%→15.7%に崩壊する
3. **最接近距離の予測**まで入れて初めて成立し、余裕が 0.20→1.50秒、
   2.5秒以上の余裕が得られる割合が 4.1%→26.7% になる。代償は抑制−7.7pt
4. 上限実験により、残る差は**距離推定の精度**と**複数音源の追跡**に帰着する
   → **精度向上が次の目標である根拠**になっている
